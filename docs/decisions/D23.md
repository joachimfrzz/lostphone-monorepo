# D23 — Arbitrage C3 : source de vérité et localisation du contenu narratif

- **Date** : 2026-07-20
- **Statut** : ACTÉ — clôt C3

## Décision

(1) CANON AMENDÉ — La source de vérité du projet est UN DÉPÔT VERSIONNÉ AU STANDARD OUVERT (Git) : historique complet, versions nommées, clonable intégralement. L'HÉBERGEUR (GitHub ou équivalent) est un choix logistique librement remplaçable, jamais un engagement — le nom du fournisseur sort du canon (la contrainte de portabilité appliquée à elle-même). L'utilisateur n'aura pas à manipuler Git : outils et IA s'en chargent. (2) ACTÉ — Le contenu narratif vit DANS ce dépôt : une histoire = un dossier AUTO-CONTENU (textes, données structurées, médias), versionné avec tout le reste. Le gel D20 devient trivial (une version nommée = l'histoire, à jamais) ; le contrat de compatibilité teste des objets précis ; portabilité totale. Principe pour les médias lourds : gestion adaptée aux gros fichiers ADOSSÉE au dépôt — mécanique exacte différée à la phase technique.

## Justification

Réponse à la question utilisateur « GitHub est-il vraiment obligatoire ? » : non — ce qui est obligatoire, ce sont les invariants (source unique, versionnée, versions nommées, portable, en fichiers lisibles humains/IA) ; Git les fournit en standard ouvert ; l'hébergeur est interchangeable en une heure. Le dossier cloud simple a été écarté (pas d'historique structuré ni de versions nommées → gel et compatibilité invérifiables).
